# Verifier Runtime Hardening

Use this checklist when a pipeline needs a separately provisioned containerized verifier rather than an existing trusted verifier backend.

## Gate sequence

1. **Keep roles separate.** Give executor, task-verifier, and test-verifier different adapter identities and containers. Do not let an executor containment proof satisfy a verifier role, and do not reuse a proof across verifier roles.
2. **Prove the runtime before semantic verification.** Build the image from a pinned base and exact client version without credentials. Accept only a runner-validated local immutable image ID such as `local@sha256:<image-id>`; reject tags, repository references, and remote digests before image inspection or Docker invocation.
3. **Create a canonical control manifest from launch inputs.** Generate one structured manifest that the launch path consumes. Include image and client identity; entrypoints; network and proxy identity; user; read-only mode; capability drops; no-new-privileges; pids limit; tmpfs; cleanup behavior; mounts by non-secret reference and policy; role-specific tool policy; and the complete command script/argv, including credential handoff semantics. Persist its digest with runner-owned probe evidence and require an exact match to authorize later use.
4. **Force every entrypoint.** Set an explicit trusted entrypoint for both verifier and proxy containers. Docker otherwise inherits an image ENTRYPOINT and can run a different program while treating the runner-supplied command as arguments.
5. **Treat model tools as part of the credential threat model.** Before mounting or copying any credential, enumerate every file/process path accessible through the model's permitted tools. If the credential is reachable, reject the role before Docker launch; do not rely on prompt instructions or file ownership alone.
6. **Make egress explicit and minimal.** A verifier that needs a remote model service must use a runner-owned allowlisted proxy or equivalent constrained path. Reject absent or mismatched proxy controls before launch; never substitute host networking or unrestricted container networking.
7. **Exercise only non-secret smoke checks until structural review passes.** Build and inspect the image, verify forced entrypoints and generated argv, and run focused regressions. Do not claim a live proof or verifier verdict until a runner-owned, credential-backed role probe succeeds under the reviewed controls.
8. **Wire the backend through the real production lifecycle.** Keep the verifier backend out of ordinary adapter/model selection, but provide one explicit runner-only opt-in with named human approval, exact runtime identity, a non-secret credential reference, and separately invoked role probes. Normal execute must construct real launchers only after it re-reads both role proofs and their artifacts from the current durable run; absent opt-in or either proof must retain the unavailable verifier surface.
9. **Make probe state transactional and resume identity strict.** Complete every fallible credential-path, image, CLI-surface, and structural-boundary preflight before writing runtime controls, proof rows, or artifacts. Commit all durable verifier state only after the role probe returns its exact expected result. Stage a fresh immutable evidence artifact first; if durable-state save fails, remove only that newly staged artifact and preserve the previously referenced evidence byte-for-byte. Normal execute must never persist explicit verifier-runtime controls: only a successful role-probe lifecycle can establish them. On resume, accept omitted controls only for durable rehydration, or an exact repeat; reject every supplied runtime, image, proxy, credential-reference, task, or approval mismatch rather than silently ignoring it.
10. **Publish evidence through a no-follow filesystem boundary.** Generate evidence paths under the run root, traverse existing parents with descriptor-relative no-follow operations (or fail closed where the platform cannot provide an equivalent), and use the same boundary for cleanup. Path validation followed by ordinary path-based writes is not sufficient: a parent can become a symlink between validation and publish or unlink.
11. **Revalidate lexical credential references at every launch.** Persist a safe project-relative credential reference, but do not resolve it into a target and forget its lexical ancestry. Reject symlink or reparse components before mounting, because post-probe replacement can otherwise change the mounted credential without changing the durable identity.
12. **Snapshot mutable settings volumes inside the verifier container.** Never bind-mount a host Claude settings directory into a credential-bearing verifier. If an explicitly authorized external operator provisions a Docker-managed volume, mount that volume read-only at a private source path and mount a distinct private tmpfs as the verifier home. In the same container and before `claude exec`, use a pinned bootstrap to make a descriptor-safe snapshot into `<home>/.claude`; hash the source before and after plus the private snapshot and require equality. Keep hashes, file names, targets, and settings contents out of logs and durable evidence. Bind the source mount, private tmpfs, bootstrap path/hash, snapshot algorithm, and image identity into the canonical controls manifest. A volume name or a successful copy is not verifier authority; preserve the unavailable backend until fresh image preflight and role-specific runner-owned proof exist.
13. **Choose and record the authority trust model before enabling settings-volume launches.** Default to an OS-separated broker/service that owns Docker, volume access, and authority state; an unbound adapter may only run credential-free image/bootstrap preflight. Do not treat Python-private objects, stack inspection, module names, callbacks, or caller-provided evidence as a strict authority boundary. If the user explicitly accepts `runner_trusted` authority, bind that exact mode into immutable runtime controls and reports, retain durable proof validation plus fresh preflight for each role, and state that malicious code already executing inside the runner process is out of scope. In either mode, normal verification authorizes exactly the canonical fresh report followed by its exact resumed tool-free verdict envelope, then consumes the authorization: bind prompts, evidence paths, role, task/run, session ID, and each stage's actual command-policy digest. Any substitution, reordering, missing session, or replay must fail before Docker or subprocess effects.

## Regression minimums

Add adversarial tests for:

- remote/tag identity rejection before Docker/image calls;
- image and proxy ENTRYPOINT override;
- credential-read attempt denied before credential/Docker access;
- missing or mismatched egress proxy rejected before launch;
- any change to a manifest field or command script changing the controls digest and invalidating old evidence;
- role-specific proof non-substitutability;
- production composition retaining unavailable verifier adapters without opt-in, rejecting a single role proof, and yielding separate real launchers only with both matching durable proofs;
- preflight or probe failure leaving `run.json`, verifier controls, proof rows, and artifact references byte-identical;
- resume rejecting each explicit verifier-control mismatch while allowing exact repeats and omitted-control rehydration;
- credentials equal to, nested below, or symlink-resolved into the mounted verifier workspace being rejected before any Docker call;
- manifest tool policy parsed from the exact `--tools` argument and matching the launched argv;
- fresh execute and no-record resume rejecting explicit verifier controls without persisting any verifier authorization;
- re-probe staging and durable-save failures preserving both prior `run.json` and the previously referenced evidence bytes;
- parent replacement by a symlink between artifact-path preparation and publish/cleanup producing no external write or unlink;
- durable credential-reference replacement with a symlink being rejected before mount or Docker calls;
- settings-volume source-root layout copying its `.claude` child to exactly `<private-home>/.claude`, never `<private-home>/.claude/.claude`;
- snapshot bootstrap rejecting symlink and special entries, source mutation between the before/after digests, and a private-copy digest mismatch without emitting settings-derived data;
- canonical controls rejecting a source-volume mount that replaces the private home tmpfs or makes either private path model-tool-visible;
- unbound settings-volume adapters rejecting both plan and launch before Docker/process effects, while a composition-root-minted authority permits only the matching role/run/task;
- preflight evidence digest equality between authority mint and adapter validation, plus rejection of malformed, stale, mismatched, or caller-forged authority data;
- authority replay to a different task or run and a second matching launch being rejected before Docker/process effects;
- durable two-role settings-volume execution rehydrating only after fresh credential-free preflight for each role, never reusing the consumed probe authority;
- normal settings-volume verification accepting only report then the exact matching resumed envelope, rejecting prompt/evidence/session/task/run/role/order/replay substitution before Docker or process effects;
- task-verifier report argv retaining its restricted read tools while the sealed verdict-envelope argv is truly `--tools ''`, with distinct manifest/authority command-policy digests;
- CLI parsing accepting every implemented credential transport and rejecting unknown values before runtime composition;
- snapshot copying tolerating partial `write(2)` results by looping until each read chunk is fully persisted, and rejecting zero/negative progress without publishing a partial private copy;
- a replacement bootstrap whose `--self-check` lies returning success being rejected before authority minting, by runner-side extraction and hashing of one regular in-image bootstrap file from a never-started exact-image container; and
- strict-mode caller-synthesized preflight evidence or authority injection failing before plan/launch; or, when the user explicitly selects `runner_trusted`, immutable evidence labeling that limitation while still rejecting absent, stale, mismatched, cross-run, cross-task, cross-role, and replayed durable proof/control state; and
- live readiness accepting only one duplicate-free JSON object whose `result` is byte-for-byte the required token, while rejecting duplicate-key orderings, JSONL, prefixes, trailing data, raw prose, empty/missing/non-string result, and whitespace variants without exposing raw stdout, stderr, or session identifiers.

## Pitfalls

- Hash the actual canonical manifest, not an abbreviated argv, because omitted security flags permit a weakened runtime to reuse old probe evidence.
- Derive the command script and digest input from the same object, because parallel representations drift silently.
- Keep test-verifier no-tools enforcement independent from task-verifier read-only enforcement, because a shared capability claim cannot prove both surfaces.
- Report build/smoke evidence separately from credential-backed live proof and semantic verifier verdicts, because they prove different claims.
- Validate the actual CLI inside the selected local image before a credential-bearing launch: parse its canonical version output, require the needed flags in its help surface, and bind the raw observation to the role proof, because an image ID alone does not prove its executable behavior.
- Keep the credential outside every model-tool-visible workspace mount after resolving symlinks, because a private in-container destination cannot protect a host path reintroduced through `/workspace`.
- Validate the complete canonical credential handoff and rendered script together with the tool argv, because a safe argv does not constrain a drifted copy destination, file mode, or shell command.
- Do not persist verifier runtime authorization before all deterministic preflight succeeds, because a failed setup otherwise leaves durable state that a later execution can mistake for approved runtime material.
- On resume, compare explicitly supplied verifier controls to the durable record before composition, because silently ignoring an override obscures an identity mismatch.
- Never use validate-then-write filesystem paths for untrusted or concurrently mutable run directories; require descriptor-relative no-follow publish and cleanup, because a symlink swap after validation redirects writes or deletes outside the run root.
- Revalidate the lexical credential reference, including every parent component, at launch rather than only its resolved target, because a post-probe symlink replacement can mount different credential material under the same durable string.
- Do not treat a Docker local volume as immutable merely because the verifier mounts it read-only; another Docker client can mutate its source. Snapshot it into a private tmpfs within the same verifier container and validate source-before/source-after/private-copy equality before starting Claude, because an external write between a separate probe and launch invalidates a durable volume claim.
- Reject absolute, escaping, or unresolved symlinks in a settings snapshot instead of reproducing them, because their target can escape the verifier's private filesystem. Classify offending entries with metadata-only checks and keep names and targets out of reports.
- Mount the volume root at a private source directory but make the bootstrap consume its `.claude` child when the provisioner copied a Claude settings folder, because otherwise the snapshot creates a nested `.claude/.claude` tree that Claude will not use.
- Pin the snapshot bootstrap into the verifier image and validate its bytes runner-side before authority minting: create an exact-image container with a forced inert entrypoint, never start it, stream the one expected regular file through a shape-safe `docker cp` archive read, hash it outside the image, and fail closed if cleanup fails. Treat an in-image self-check only as a redundant capability check, because altered image code can lie about its own bytes.
- Use one canonical preflight-evidence payload for both settings-volume authority minting and validation, because hashing different subsets makes every valid authority look stale.
- Do not accept a static constructor, callback, boolean, caller-supplied digest, preflight-evidence object, or authority-injection factory parameter as settings-volume authority; mint and inject it only inside the composition root after durable-proof validation, because same-process callers can forge or transplant deterministic data objects.
- Bind settings-volume authority to the exact durable run and task at `plan()` and `launch()`, then consume it after the matching launch, because a role/image/volume-only capability can be replayed across tasks in the same process.
- Rehydrate settings-volume launchers with fresh credential-free preflight for both roles after validating their durable proofs; a probe-local authority is consumed and process-scoped, so normal execution otherwise remains permanently unavailable after successful probes.
- Bind the normal verification continuation to the canonical verdict-envelope request and its actual tool argv, not only to a resumed session ID, because a matching session can otherwise spend the single continuation on an arbitrary tool-enabled prompt.
- Keep a settings tmpfs parent writable/traversable by the configured non-root verifier user, but create and normalize the credential-bearing `<home>/.claude` child to `0700` inside the bootstrap; Docker tmpfs ownership options are not a portable substitute for an executable non-root mount contract.
- Loop on low-level file writes during descriptor-safe snapshot copy, because POSIX `write(2)` may complete only part of a buffer and a single call can produce a digest-mismatched private settings tree.
- Before a credential-bearing settings-volume probe, run a no-network, non-semantic snapshot smoke with the production user, mounts, tmpfs, and bootstrap. Measure only aggregate source metadata when calibration is needed; never emit names or contents. Size the private tmpfs as a fixed canonical limit and reserve capacity for inode, dentry, directory, and path metadata as well as regular-file payload, because a payload-only limit can still exhaust tmpfs.
- Diagnose credential-backed nonzero exits through the structured CLI envelope, not stderr alone: check `is_error`, documented HTTP status, and OAuth/rate-limit markers in memory and print only a bounded category. A CLI can emit JSON with `subtype=success` and `is_error=true` while stderr is empty; a generic `unknown-exit` must not be called a runtime or keychain failure. Compare host and contained probes with the same model and effort, then compare source and volume-file size/mtime metadata without reading, printing, or hashing credential bytes; a settings snapshot can remain stale after host authentication refresh even while `auth status` reports logged in. A metadata difference is a diagnosis, not permission to refresh the volume or verifier proof.
- For any new or renewed credential copy, keep the user's authorization and the platform's confirmation gate distinct: scope source files, destination volume, process/network controls, and permitted metadata checks, then wait for the write approval. If approval expires, do not retry, rephrase, or route around the blocked write; report that no copy occurred and require a new user decision.
- Enforce snapshot payload, entry-count, and path-byte budgets during every descriptor-safe pre-copy digest and again while copying each entry and chunk. Charge each copied byte before its first destination write and reject budget growth during traversal, because a mutable volume can grow a file or add entries after preflight and otherwise consume private storage before the final digest check detects the race.
